# 🤖 LandarevAI

**LandarevAI** — это веб-приложение на базе **FastAPI**, предоставляющее интерфейс чата с искусственным интеллектом (через OpenRouter API) с сохранением истории в базе данных. Проект включает CRUD-эндпоинты для управления сообщениями и ролями (в режиме отладки), а также гибкую архитектуру с репозиториями и сервисами.

---

## 🚀 Возможности

- ✅ Чат с AI-моделью (интеграция с OpenRouter)
- ✅ Сохранение всей истории сообщений в базе данных (SQLite по умолчанию)
- ✅ Автоматическое создание ролей «Пользователь» и «LandarevAI» при первом запуске
- ✅ Отображение сообщений с поддержкой **Markdown** (как на сервере, так и на клиенте)
- ✅ Индикатор печати и адаптивный интерфейс (тёмная тема, мобильная версия)
- ✅ Тестовое REST API для управления сущностями (только в режиме `DEBUG`)
- ✅ Страница ошибок с автоматическим перезагрузом через 30 секунд
- ✅ Возможность очистить всю историю чата одной кнопкой

---

## 🛠 Технологии

- **Backend**: FastAPI, SQLModel, Pydantic, OpenRouter API
- **Frontend**: HTML, CSS (кастомные), JavaScript (vanilla), Marked.js
- **База данных**: SQLite (по умолчанию), поддерживается любая SQLAlchemy-совместимая СУБД
- **Шаблонизация**: Jinja2
- **Безопасность**: Bleach для санитизации HTML, экранирование в шаблонах
- **Зависимости**: управление через `pip` + `venv`

## ⚙️ Установка и запуск

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/your-username/Landarev-AI.git
   cd Landarev-AI
   ```

2. **Создайте виртуальное окружение и активируйте его:**
   ```bash
   python -m venv venv
   source venv/bin/activate   # Linux/Mac
   # или
   venv\Scripts\activate      # Windows
   ```

3. **Установите зависимости:**
   ```bash
   pip install -r requirements.txt
   ```

4. **Настройте переменные окружения** – создайте файл `.env` в корне проекта, скопировав `.env.example`:
   ```env
   DATABASE_URL=sqlite:///./test.db
   OPENROUTER_API_KEY=your_api_key_here
   OPENROUTER_API_BASE_URL=https://openrouter.ai/api/v1
   DEBUG=True   # или False для продакшена
   ```

5. **Запустите приложение:**
   ```bash
   uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
   ```

6. Откройте браузер по адресу: [http://localhost:8000](http://localhost:8000) – вы будете автоматически перенаправлены на страницу чата.

## 📌 Доступные эндпоинты

### Основные страницы

| Метод | URL          | Описание                                   |
|-------|--------------|--------------------------------------------|
| GET   | `/`          | Перенаправляет на `/chat`                  |
| GET   | `/chat`      | Страница чата с историей из БД             |
| GET   | `/error`     | Страница ошибок (параметр `?code=XXX`)     |

### API чата (используются клиентским JS)

| Метод | URL          | Описание                                       |
|-------|--------------|------------------------------------------------|
| POST  | `/chat/`     | Сохраняет новое сообщение в БД (JSON-тело)     |
| DELETE| `/chat/`     | Удаляет **все** сообщения из БД                |

### API AI (вызывается из клиента)

| Метод | URL                         | Описание                                                      |
|-------|-----------------------------|---------------------------------------------------------------|
| GET   | `/api/v1/ai/?message=...`   | Отправляет запрос к OpenRouter с полной историей чата и возвращает ответ AI |

> **Примечание:** AI получает весь контекст из БД, поэтому поддерживается многопользовательский диалог (в рамках сессии).

### Тестовое API (работает только при `DEBUG=True`)

Префикс: `/api/v1/test`

| Метод   | URL                         | Описание                                   |
|---------|-----------------------------|--------------------------------------------|
| GET     | `/message`                  | Получить все сообщения                     |
| GET     | `/message/{message_id}`     | Получить сообщение по ID                   |
| POST    | `/message`                  | Создать новое сообщение (JSON)             |
| PUT     | `/message/{message_id}`     | Обновить сообщение по ID                   |
| DELETE  | `/message/{message_id}`     | Удалить сообщение                          |
| GET     | `/role`                     | Получить все роли                          |
| GET     | `/role/{role_id}`           | Получить роль по ID                        |
| POST    | `/role`                     | Создать новую роль                         |
| PUT     | `/role/{role_id}`           | Обновить роль                              |
| DELETE  | `/role/{role_id}`           | Удалить роль                               |

Все тестовые эндпоинты возвращают JSON вида `{"result": ...}`.

## 🗄 База данных

По умолчанию используется **SQLite** (файл `test.db` в корне). При первом запуске (при обращении к `/chat`) таблицы создаются автоматически, а также добавляются две стандартные роли:

- `Пользователь` – для сообщений от пользователя
- `LandarevAI` – для сообщений от AI

Для использования другой СУБД (PostgreSQL, MySQL) измените `DATABASE_URL` в `.env`.

## 🎨 Интерфейс и взаимодействие

- **Стартовый экран** – приветственное сообщение и поле ввода по центру.
- **Отправка сообщения** – после первого сообщения интерфейс переключается в режим чата: история становится видимой, поле ввода смещается вниз.
- **Сохранение в БД** – каждое сообщение (и пользователя, и AI) сохраняется в базу данных.
- **Очистка чата** – кнопка 🗑️ в хедере удаляет все сообщения и возвращает интерфейс в исходное состояние.
- **Markdown** – сообщения от AI рендерятся на сервере (через `markdown` + `bleach`) и дополнительно на клиенте (через `marked.js`) для безопасности и красоты.
- **Индикатор печати** – отображается во время ожидания ответа от AI.
- **Адаптивность** – интерфейс корректно отображается на мобильных устройствах.

## 🧪 Разработка и отладка

- Для включения тестового API установите `DEBUG=True` в `.env`.
- Для просмотра ошибок используйте страницу `/error?code=XXX` (доступны коды 400, 401, 403, 404, 500, 502, 503, 504).
- Логирование настроено через стандартный модуль `logging`. Уровень логов зависит от `DEBUG`.
- Для проверки работы с БД можно использовать тестовые эндпоинты.
